# 附录 A 自测题库

这套题用于检查你能否把概念转成系统决策。先独立作答，再查看末尾参考答案。开放题没有唯一实现，但必须给出状态、证据、失败边界和验收方法。

## A.1 基础与模型

2. ReAct、Plan-and-Execute、Reflection 分别适合什么不确定性？何时 Reflection 只会增加成本？
3. 为什么 Chat Template 和 Special Token 错误会破坏工具调用，即使模型权重完全正确？
4. 比较 Greedy、Top-p 与 Constrained Decoding：各自优先优化什么？
5. Transformer 中缩放点积为什么除以 $\sqrt{d_k}$？因果 Mask 在训练和推理时分别约束什么？
6. SFT 的 Completion Mask、Packing 与 Padding 各自解决什么问题？

12. 长任务压缩后必须保留哪五类信息，才能继续执行而不是只写出“漂亮摘要”？

## A.7 参考答案

1. Agent 需要观察、决策、行动、更新状态并判断继续/终止；一次函数调用没有持续状态与闭环。
2. ReAct 适合局部探索；Plan-and-Execute 适合可分解长任务；Reflection 适合可从可验证反馈修正的任务。没有新证据或验收器时，反思容易重复措辞。
3. 模板决定角色边界和工具协议，Special Token 决定序列分隔与终止；错位会让模型学习到的控制格式失效。
4. Greedy 强调确定性；Top-p 在累计概率质量内采样；Constrained Decoding 保证输出满足语法/Schema，但不保证语义正确。
5. 缩放控制点积方差和 Softmax 饱和；因果 Mask 在训练时防止看见未来 Token，在自回归推理时保持同一条件分解。
6. Completion Mask 只对目标回答计损失；Packing 提高 Token 利用率并隔离样本；Padding 对齐 Batch 形状但不应贡献损失。
7. Schema 应限制订单号、收件人、正文和审批令牌；读工具声明可重试错误，写工具使用业务幂等键并区分拒绝、冲突、超时与结果未知。
8. 外部文本不能获得系统指令或工具权限；必须通过来源标记、数据隔离、Allowlist、参数校验和审批约束控制权。
9. 一次性 RAG 在推理前固定 Top-K；Agentic Search 依据中间证据反复选查询与数据源。达到证据充分、边际收益低、预算上限或不可解决冲突时停止。
10. Multi-query/HyDE 生成候选查询或表示，RRF 融合多路排序，Cross-encoder 在候选集上精排。
11. 工作记忆保存当前状态，情节记忆保存经历，语义记忆保存归纳知识，外部事实源保存可重新验证的数据；任何记忆都不能绕过当前权限与审批。
12. 目标与约束、已确认事实及来源、已完成动作及副作用、未决问题/风险、下一步与验收条件。
13. 前两者采样多个完整答案；ToT 显式维护分支；MCTS 用选择—扩展—评估—回传分配搜索预算。更高成本只在评价器能区分候选时有价值。
14. 至少包括任务成功、工具/轨迹正确性、安全违规、延迟、成本、恢复率和用户修改率。
15. MRR 重视第一个相关结果的位置；nDCG 处理多个分级相关结果。答案存在等价分词或局部重合时 Token F1 更稳健。
16. 随机交换候选顺序、控制长度、盲化模型来源、加入人工金标并测一致率；必要时使用多评审与规则指标交叉验证。
17. PPO 使用在线回报/优势并限制策略更新；DPO 使用偏好对；KTO 可使用单样本好/坏标签；RLVR 使用可程序验证结果。
18. ORM 给完整输出打分，PRM 给中间步骤打分；有漏洞的 PRM 会奖励冗长、伪步骤或“看起来正确”的轨迹。
19. 权限限制可做范围，沙箱限制影响面，审批确认高风险意图，审计保留证据，补偿动作处理不可原样撤销的外部副作用。
20. 比较算术强度与 Ridge Point；低 MFU 也可能来自访存、通信、CPU 等待、碎片、同步或负载不均。
21. Prefill 并行度高、偏计算；Decode 逐 Token 且反复读权重/KV，常偏带宽。TTFT 是首字等待，ITL 是连续输出流畅度。
22. 层数、Batch、序列长度、KV 头、头维度和精度共同决定容量；GQA/MQA 让多个 Query Head 共享更少 KV Head。
23. DP 切 Batch，TP 切层内张量，PP 切层，SP 切序列/激活；TP/SP 的频繁层内通信最依赖低延迟高速域。
24. 分片参数、梯度和优化器状态；激活、临时 All-Gather、通信 Bucket、内核 Workspace 与碎片仍占显存。
25. 至少含 Task ID、Sequence、Event ID、Type、Schema Version、Timestamp；审批、权限、产物版本、错误和终局状态不可丢。
26. 受控 Schema 可校验组件、字段和权限，把渲染/副作用留给应用；任意代码会扩大注入、XSS 和越权面。
27. SLO 同时约束成功率、尾延迟、恢复和成本；只对可判定的瞬时错误重试，熔断持续故障，降级必须可见，高风险写操作用补偿或版本回滚。
28–32. 按题目逐项验收；答案若缺少状态边界、版本/来源、失败路径或量化指标，不能算完整设计。
