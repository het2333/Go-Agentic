# 前言

## 从一次看似成功的执行开始

设想一个采购助手回复：“供应商变更已完成。”这句话可能来自三种完全不同的系统：模型猜测了结果，程序提交了请求但没有检查响应，或者 Agent 读取了当前订单、获得审批、执行变更并再次查询目标系统。三者的文字可以同样流畅，工程可信度却截然不同。

Go Agentic 研究的是第三种系统。课程把 Agent 看成一个在 Environment 中运行的有界决策循环：它观察状态，选择动作，调用 Tool，检查结果，更新记录，并在完成、失败、风险过高或预算耗尽时停止。模型提供语言与决策能力，Runtime 负责状态、权限、恢复和审计，Verifier 用证据判断任务是否真的完成。这个分工贯穿全部 25 章。

## 一条从闭环到生产系统的课程主线

课程顺序由“下一项工程能力依赖什么”决定。第 1–3 章建立 Model、Agent、Harness、Runtime 与 Environment 的边界；第 4–7 章实现可运行、可终止的 Loop；第 8–10 章加入检索、记忆、Context 与外部协议；第 11–12 章建立优化、评测、可观测性和安全门。

第 13–16 章把这些能力放进任务执行、Deep Research 与多 Agent 项目，并用期中验收暴露缺失的证据和恢复路径。第 17–19 章再从 Token、Attention、训练状态和偏好目标解释模型为什么产生某类行为；第 20–22 章把同一问题放到 GPU、推理服务和分布式训练中计算容量、通信与成本。第 23–24 章把运行状态交给用户界面和生产平台，第 25 章要求用基线、消融、安全评审和复现包完成毕业项目。

因此，数学与系统章节不是脱离应用的理论插曲。Attention 的复杂度会改变 Context 策略，KV Cache 决定并发上限，训练数据边界会影响 Tool Schema 遵循，队列与幂等性决定一次正确决策能否安全落地。毕业设计则把这些局部判断收束成一套可评测、可审计、可恢复的系统证据。

## 按目标选择三条学习路径

- **Agent 应用工程：** 学完第 1–16 章后进入第 23–25 章。适合希望先交付企业自动化、研究或工具型 Agent 的读者；模型训练与大规模基础设施可在需要时补学。
- **全栈 Agentic AI：** 按第 1–25 章顺序推进。适合需要同时解释模型行为、训练方法、推理容量与生产平台取舍的读者。
- **模型与系统进阶：** 先完成第 1–12 章，再集中学习第 17–22 章。适合已经掌握 Agent 闭环，希望补齐 Transformer、后训练、GPU 与分布式系统基础的读者。

无论选择哪条路线，都保留同一条安全底线：模型输出不是执行结果，Schema 正确不是业务正确，指标平均值不能掩盖高风险失败，高风险副作用必须绑定权限、预览、审批、幂等键和可追踪结果。

## 如何使用这门课程

前 16 章只要求基础 Python、命令行和模型 API 概念。第 17–22 章会用到线性代数、概率、PyTorch 与计算机系统知识；公式均服务于可计算的工程问题，不要求先拥有大规模 GPU 集群。

每章都建议保留一份运行记录：任务契约、命令与环境版本、输入 Fixture、实际输出、一个失败样本、修复依据和最终验收。当前维护的离线实验位于 `code/go-agentic/`，优先使用确定性数据，可在无付费 API、无大模型下载的环境中验证核心语义。阅读表格和公式之后，请改变参数、制造失败，再说明系统为何恢复或停止。

学完一章的标准不是记住框架名称，而是能回答四个问题：权威状态在哪里，什么证据支持下一步，哪类失败允许重试，谁或什么规则可以终止执行。带着这四个问题进入课程，你会逐步得到一套能够迁移到新模型、新工具和新业务的工程方法。
